# Implement keyboard navigation and command-palette enhancement layer

## Owning ADRs

- `adr/0015-define-progressive-keyboard-enhancements.md`
- `adr/0013-define-semantic-tui-widgets.md`
- `adr/0014-define-responsive-terminal-theme-system.md`

## Scope

Implement an optional, no-framework browser enhancement layer that adds
keyboard-first interactions only on widgets that opt in through explicit markup
attributes.

## Exit criteria

1. A versioned, cacheable JavaScript asset is generated by mkpage and included
   when keyboard enhancements are enabled.
2. Keyboard interactions include `j/k`, arrow navigation, `Enter`, `Esc`, `/`,
   `?`, and configured `g`-prefixed route shortcuts.
3. Runtime never activates on presentation classes alone; interaction follows
   widget attributes.
4. Pointer/touch interactions update the same active-state model as keyboard
   interactions.
5. Inputs and editable controls bypass global shortcuts.
6. No-JS navigation remains complete and links retain native semantics.
7. Tests verify build output, DOM behavior contracts, and teardown/overlay
   cleanup.

## Delivery notes

- Keep enhancement runtime opt-in and compatible with v0.1 no-JS requirements.
- Route shortcuts are exposed through page-level runtime configuration so they can
  be remapped per site.
- Enhancement JS is included via `site.enhancements.keyboard` in theme layouts.
